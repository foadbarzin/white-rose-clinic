# معماری پیشنهادی - White Rose Clinic V2

## خلاصه
سیستم مدیریت کلینیک با سه لایه اصلی:
- **کلاینت (UI):** HTML/CSS/JavaScript راست‌چین و فارسی، اجراشده در Web App Apps Script.
- **سرور (Apps Script):** منطق دامنه، احراز هویت، مجوزها، اعتبارسنجی، محاسبات، audit و migration.
- **داده (Google Sheets جدید):** ذخیره‌سازی ساختاریافته بدون داده نمونه.

## تصمیم‌های قطعی (اثرگذار بر معماری)
- واحد پول: **تومان**
- تقویم: **نمایش شمسی، ذخیره‌سازی تاریخ استاندارد**
- ورود: **نام کاربری و رمز عبور**
- کمیسیون: **درصدی و مبلغ ثابت، قابل تنظیم برای پزشک و اپراتور**
- تخفیف: **فقط با مجوز مدیر**
- مالیات: **قابل تنظیم**
- پایگاه داده: **Google Sheets فایل جدید**
- مخزن: خصوصی `https://github.com/foadbarzin/white-rose-clinic`

## الگوی ارتباطی
```text
Browser (RTL UI)
  -> google.script.run.apiCall(action, payload)
     -> AuthN/AuthZ
     -> Validation
     -> Domain Service
     -> Repository (Sheets)
     -> Audit / Lock / Cache
  <- Result / Error
```

### اصول
1. **دروازه واحد API:** فقط یک نقطه ورود سروری برای فراخوانی‌های کلاینت.
2. **جداسازی لایه‌ها:** UI بدون دسترسی مستقیم به شیت؛ سرویس‌ها منطق دامنه، ریپوها I/O.
3. **بدون داده آزمایشی:** فقط سربرگ‌ها و ساختار در زمان Setup ساخته می‌شوند.
4. **قفل‌گذاری نوشتن:** استفاده از `LockService` برای عملیات حساس (شماره فاکتور، پرداخت، کمیسیون).
5. **حذف نرم:** رکوردها حذف فیزیکی نمی‌شوند؛ وضعیت/پرچم حذف ثبت می‌شود.
6. **Audit trail:** ثبت اقدامات مهم (ایجاد/ویرایش/حذف نرم/تغییر مجوز و تنظیمات مالی).

## ماژول‌های دامنه (فازهای بعد)
- مشتریان، پزشکان، اپراتورها، خدمات
- فاکتورها، اقلام فاکتور، پرداخت‌ها
- درآمد، هزینه‌ها
- قواعد کمیسیون و محاسبه کمیسیون
- گزارش‌ها و داشبورد
- کاربران، نقش‌ها، تنظیمات

## محدودیت‌های Apps Script / clasp (طراحی هدف)
- ادیتور Apps Script مسطح است؛ نام فایل‌ها باید در کل پروژه یکتا باشد.
- فایل‌های کلاینت قابل include باید `.html` باشند (CSS/JS داخل `<style>`/`<script>` یا فایل‌های HTML جدا).
- ترتیب بارگذاری `.gs` با `filePushOrder` (در `.clasp.json` محلی) مدیریت می‌شود.
- `rootDir` پیشنهادی: `src` (در فازهای کدنویسی).

## امنیت (پایه)
- احراز هویت داخلی با نام کاربری/رمز (رمز به‌صورت هش+salt در فاز پیاده‌سازی).
- مجوزسنجی سمت سرور برای هر `action`.
- تخفیف فقط با نقش/مجوز مدیر؛ مالیات و قواعد کمیسیون قابل تنظیم کنترل‌شده.
- عدم نگهداری شناسه واقعی Script/Sheet، توکن و رمز در مخزن.

## خارج از دامنه فاز یک
- پیاده‌سازی کد سرور/کلاینت، اتصال Google Sheets، ساخت شیت‌ها، احراز هویت واقعی، CRUD، فاکتور، کمیسیون، گزارش و انتشار.
